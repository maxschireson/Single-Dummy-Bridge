## Goal

Max wants task lists that can be checked in and out and experiments that come and go, for a project that is moving from fixed generations to a standing population. This channel's README is a bootstrap written in an hour; design what should replace it.

Cover: the life cycle and file format of tasks and experiments (leases that expire, dependencies, results kept when negative); the tool; how an executor (a short-lived agent given one task) is briefed so a task file is enough; how the queue is prioritized by value for effort; the metrics that say whether there are too few thinkers or too few executors; whether GitHub issues should mirror the files so Max can read the queue on a phone; and how this relates to the two boards that exist (`box/coordination`, `fleet/azure`).
