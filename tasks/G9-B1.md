## Goal

Design the bidding half of "a player arrives with a convention card". Three things:

1. **Card IR fields.** The controlled field list for bidding agreements (`configs/cards/_fields.json`). Start from what `rule_bidder.Settings` can express, then list what real cards (ACBL card, WBF card, USBF system summary form) declare that it cannot, marked as not yet executable.
2. **Compile.** Card IR to rule-bidder settings; which fields are required, defaulted or refused.
3. **The rule filter** (architecture 4.2), exactly: the factor for each call a seat made; when the card "says nothing" (the general placing procedure, the empty meaning); negative inference from the order of a table and when a table counts as complete; soft edges; evaluation on hand types (lengths and honour bits) with caching; expected cost per board.

Also: the first profiles and where each one's reference rules come from, and how E9-1 and E9-2 will be measured.

## Done when

`docs/gen9/bidding.md` on branch `feature/gen9-bidding-design`, three pages at most, submitted here. Then start G9-B2 without waiting for the review.

## Context

docs/gen9/architecture.md on feature/gen9, sections 3, 4.1, 4.2. The rule bidder already has the abstraction this needs: every call has a meaning `M` (point range, length ranges, a private test), `explain(state, seat, token)` returns it, and tables are ordered. `docs/gen8_systems.md` lists what Gen 8 left undone (card readers, a gate computed from a descriptor, detection).

Constraints: nothing from the EPBot/BBA engine or its `.bbsa` cards. The filter must be exactly inert without a card.
