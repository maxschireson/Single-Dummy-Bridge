# DDS bidding: first 10,000-deal result — 8 November 2026

The first candidate finished 10,000 training deals (20,000 auctions, 79 PPO
collection/update batches). Its fixed 1,000-deal held-out development screen
showed **no demonstrated improvement** over the original BEN net-only bidder.

| Measurement | Result |
| --- | ---: |
| Held-out paired deals | 1,000 |
| Total IMP difference, candidate minus BEN | -3 |
| IMPs per paired deal | -0.003 |
| Descriptive 95% paired t interval | [-0.095, +0.089] |
| Wins / losses / ties | 15 / 20 / 965 |
| Pairs with different auction transcripts | 48 |

The parent, original and older-league opponent are all the same frozen B0 at
this first stage. The three reported columns therefore describe one comparison,
not three independent replications. A tie can also conceal different contracts
with the same duplicate score.

This was the predeclared **development screen**, not the 10,000-pair confirmation
match. Its negative mean did not pass the screen, so no confirmation match was
launched and no model was promoted. The unchanged campaign has advanced to the
50,000-training-deal stage, continuing from the 10k candidate. Its next screen
uses fresh development deals.

The saved run reported about 28.6 minutes of active time
through this screen. Two unexplained worker interruptions made wall-clock
completion substantially longer. Both were recovered from the model/Adam
checkpoint and persistent DDS cache. No Python exception established their cause.

All bidding was greedy net-only during evaluation; DDS scored completed contracts.
Neither actor nor critic received hidden hands, DDS values, or future calls.
The exact 10k model/optimizer snapshot was retained before later updates, as
`Bridge_DDS_Bidding_10000_Checkpoint_2026-11-08.zip`.

This result does not establish that DDS-reward training cannot improve bidding.
It establishes that this first 10k-deal PPO candidate has not shown a gain on
this development sample. Source: `evaluations/a001-s0-dev/summary.json` and all
1,000 paired records. Source implementation commit: `bdc21cb6ac942191e669c04d27b99b37c4d26fab`.
