# Diagnostic RNG marker protocol v1 — not production

The comparison extends the isolated claim-state protocol to BEN families 1082 and 2561, with three concurrent self-play workers. Persistent and recycled servers both use the diagnostic wrapper and the same captured initial claim state. This does not establish equivalence to unchanged production BEN or recover the dead server's unknown RNG state. Root/tie-audit cards, probabilities, seeds, auctions and scores, and final claim state must match; timing-budgeted gap-fork volume is outside the fingerprint.

The separate transaction probe uses an existing episode/receipt fixture and captured diagnostic RNG states. It writes a fresh immutable generation containing episode, receipt bound to pre/post RNG hashes, RNG state, and a hash manifest. Files and directories are fsynced before a single CURRENT marker is atomically replaced and its parent directory fsynced. Readers follow only CURRENT, verify the manifest and all hashes, and verify receipt episode/RNG bindings. A stale pre-state is rejected. An unreferenced partial generation is never automatically adopted or retried.

Actual SIGKILL tests stop the writer after directory creation, each of three data files, the manifest, generation directory fsync, parent fsync, temporary marker fsync, marker replacement, and final parent fsync. Recovery must return the old complete generation before marker replacement or new complete generation afterward. Missing/corrupt state and stale pre-state must fail closed. This is process-crash testing, not simulated storage power loss.

Production integration remains unimplemented: a single supervisor/writer lock must protect both normal and BEN commits, authoritative receipts must expose only accepted generations, normal commits must carry the current BEN state unchanged, and export/snapshot/restore must resolve the same commit marker. Historical receipts must remain byte-preserved. Server/worker exit gates must precede transaction publication. Integrate and test those paths in a NEW diagnostic version before considering a new production cohort. Candidate1bd remains STOP; production65a remains frozen with unresolved003062. No launch or adoption is authorized by these tests.
