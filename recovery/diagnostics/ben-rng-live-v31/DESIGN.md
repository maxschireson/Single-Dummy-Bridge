Production 65a is untouched and stopped. Candidate1bd remains STOP. All records here are diagnostic, never eligible production records. Isolated claim RNG is a deliberate diagnostic behavior change, not unchanged-BEN equivalence or recovery of the original dead server RNG.

The previous collision-safe adapter was exercised with eight newly played records: BEN1082/2561 and self1930-1935. Three normal futures interleave with the serial BEN lane. An additional comparison to all eight prior V3 plays is only seven-of-eight exact. Self1934 contains seven fewer audit nodes, alongside shared-compute-budget skips. Its root and all33 common nodes match exactly, including actions/probabilities/scores. This is evidence of variable captured audit volume, not grounds to relax the gate. repeat-summary.json and detailed differences preserve the finding. The historical semantics helper incorrectly assumed gap nodes start with gap; actual names start root/gap, so those old fingerprints also include gap nodes. No historical reports were rewritten or gate relaxed.

failure_probe.py plays real BEN1082 then injects SIGKILL either into the worker before successful result delivery or into the server before lifecycle acceptance. It checks that the private RNG advanced to the reference poststate, the future rejects, and no accepted journal marker is created. These are post-play failure checks, not killing the collector while futures are in flight. Raw logs retain actual exit codes.

The bounded synthetic marker test roundtrips and compares structural equality at depths128/512/1024/2015/8128. It succeeds in this environment; there is no demonstrated recursion failure. However the8128 marker alone is4,095,409bytes with the sampled marker shape, and each generation embeds its ancestors. Full storage/recovery work grows quadratically. Production-scale journal storage/read performance remains unvalidated. A compact SHA-bound parent-reference format with iterative validation is the next design step; do not simply raise recursion limits or claim full-scale recovery validated.

Remaining: immutable protocol/runtime identity enforced during loading/commit, efficient parent references and full-scale recovery, in-flight collector interruption plus owned-child cleanup, restore/resume against persistent reference, concurrent snapshot consistency, and power-loss behavior. No adoption, failure clearing or production restart is authorized by these diagnostics.
