## The code

Until this commit a plan could name exactly one policy release, so a cohort could not hold `7s-32`
and `71s-32` together.

- `ops/prepare_gen7_alpha.py`: a plan's `artifacts` are exactly the policy releases its bots use.
  A bot names one with `"policy": "gen7_policy_<name>"`; without it, `gen7_policy`. The first
  release keeps its path in the run (`artifacts/gen7/policy.npz`), so `7s-32` keeps the identity it
  has in phase 1 (`f0a57859...` on the capture capsule); another sits at
  `artifacts/gen7/<key>.npz`. The manifest's `gen7_alpha` block lists every bot's release when there
  is more than one.
- Nothing in the runtime changed: the player already read its policy path from the bot's spec.
- Everything in the [self-play notice](gen7_selfplay_2026-11-12.md) still holds: the collector
  accepts a bot playing itself, gap forks and the guess-size fields are recorded, and a drained Gen 7
  cohort can be the source run.

## Switching a collector

1. Drain the 7.0 cohort: `STOP`, wait for the collector and for the feed to carry every board.
2. Check out `9f5ec19` or later in a new directory, restore the model releases (v4.1 among them),
   build DDS, run `python -m unittest discover -s tests -p "test_gen7*.py"`.
3. `python ops/prepare_gen7_alpha.py --source DRAINED_RUN --run NEW_RUN --plan configs/round71-compare.json`
   (or `round71-ben.json`). The source's bots are kept; the plan's `7s-32` must be the bot the
   source has. A collector that plays the BEN pairs and the comparison in one cohort merges the two
   plans' pairs, rosters and bots.
4. Preflight with `ops/smoke_gen7.py`, start `ops/gen5_runtime.py`, publish to a new feed branch,
   register it. The dashboard knows `71s-32` since `gh-pages` `03d02fc`; a feed with another id for
   the 7.1 bot would stop its report.
